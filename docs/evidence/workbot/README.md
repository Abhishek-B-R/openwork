# Cloud Workbot verification

These are new captures of the production Den web build, backed by an isolated
Den MySQL database and the real Den authentication/member routes. The member,
workspace and requests are synthetic. No external message was sent.

The conversation and draft are generated by genuine local Qwen inference routed
through the **production AI Gateway proxy**, running the pinned native agent in
a non-root Linux worker container. Gateway authorization, provider grant and
quota records were **isolated in-memory test fixtures**; they were not written as
real model grants. Membership, Den sessions, OpenWork MCP and encrypted MySQL
persistence were real. Both injected MCPs connected before inference. A separate
OpenWork skill read returned HTTP 200 without a tool/RPC error. See
[gateway wire](gateway-wire.json) and [natural conversation](natural-conversation.json).

The browser cannot submit new messages because this preview workspace has no
usable real Gateway model grant. Its neutral blocked banner and disabled composer
are intentional. Existing conversation/files remain readable. The draft is a
generic proposal from the test model; it is not a claim about connected calendar,
meeting or customer data. No generated response is embedded in the product.

- [Conversation](conversation.jpg): real persisted user message, generated reply
  and saved-draft card. The model result appears once; tools and counters are hidden.
- [Open draft](open-draft.jpg): the actual encrypted file is loaded through Den.
- [Files](apps.jpg): actual saved files, with the existing connections entry point.
- [Calendar](calendar.jpg): no invented meetings or connection success.
- [Mobile](mobile.jpg): the conversation and composer at 390 × 844.

The desktop reference comparison uses 1440 × 928, excluding the 32-pixel OS strip
from the Paper Messages artboard. Geometry is 60-pixel header, 620-pixel centered
conversation and 420-pixel contextual sidebar. Native app tokens and controls are
used throughout. Applied DESIGN rules: P1, P5, P10, P11, S4, C3, C5 and T5.

[Cloud checks](cloud-verification.json) record real database concurrency/fencing,
image build, hardened worker health and restart. The ordinary desktop typecheck
has an existing unrelated ES2024 library-target issue; the full check passes
with an ES2024 library override. Production web/API builds pass.

The real-inference checks used the initial Linux image; its exact identity is
recorded separately. The final image includes the additional exact-session
revocation check and schedule bounds, passes its full build, and was verified
for production-mode startup and restart. These are distinct verification steps.

The deployment now includes an opt-in Helm worker and an image target in the
existing EE publishing workflow. **No hosted deployment or existing organization's
production Gateway grant was verified.** The opt-in `scripts/smoke-workbot.ts`
checks an already-enabled cloud workspace once a real session is supplied.
